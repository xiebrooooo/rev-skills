# binary-triage fixtures

Three small native binaries, built from source in this directory. Nothing is committed as a
binary artifact: `fixtures/src/` holds the sources, `build.sh` / `build.ps1` produce
`fixtures/build/`.

```bash
sh fixtures/build.sh          # POSIX
pwsh -File fixtures/build.ps1 # Windows
```

Artifacts are renamed to extension-less names on Windows too, so every consumer addresses
`fixtures/build/triage_clean` regardless of platform. Analysis tools work by content, not
by extension, so dropping the `.exe` costs nothing.

---

## Measured properties

Recorded from a MinGW-w64 build on Windows, x86-64. Reproduce with `sh fixtures/build.sh`
followed by the probe in the *Reproducing the numbers* section below.

| Fixture | Bytes | Sections | Symbols (`nm`) | Whole-file entropy | Densest section |
|---|---|---|---|---|---|
| `triage_clean` | 83142 | 16 | > 0 | 5.309 | under 7.0 |
| `triage_stripped` | 40960 | 9 | 0 | 5.865 | under 7.0 |
| `triage_packed` | 115926 | 17 | > 0 | **6.399** | `.blob` 32768 B @ **7.995** |

Two of these numbers exist to defeat lazy heuristics:

- **`triage_stripped` has higher whole-file entropy than `triage_clean`** (5.865 vs 5.309).
  Stripping removes low-entropy debug and symbol data, leaving the dense parts
  proportionally larger. "Higher entropy" does not mean "more suspicious".
- **`triage_packed`'s whole-file entropy is 6.399** while the section that matters is at
  7.995. A procedure that scores the file first and only localises when the file figure is
  high never fires here.

## Ground truth

The facts a correct triage must recover. These are the basis for `expected.md`.

| Fixture | Ground truth |
|---|---|
| `triage_clean` | **Not stripped.** Symbol `planted_marker_fn` resolvable by name. Literal `REVSKILLS_MARKER_CLEAN_v1` present in `.rodata`. Dynamically linked against the platform C runtime. No section above entropy 7.0. No packer magic bytes. |
| `triage_stripped` | Same source, after `strip`. **Zero symbol table entries.** `planted_marker_fn` no longer resolvable by name. The literal `REVSKILLS_MARKER_CLEAN_v1` **is still present** — stripping removes names, not data. Fewer sections than `triage_clean`. |
| `triage_packed` | Contains a custom section `.blob` holding 32768 bytes of deterministic pseudo-random data at entropy **7.995**. Literal `REVSKILLS_MARKER_PACKED_v1` present. **It is not actually packed**: `.blob` is read-only, `.text` sits at 6.252, and the entry point is inside a normal executable section. This is the honest false-positive control. |

---

## Why these three

The set is built so that each fixture falsifies a specific over-eager conclusion:

- **`triage_clean`** → baseline. A triage that cannot profile a plainly normal binary is
  broken before it faces anything interesting.
- **`triage_stripped`** → catches "no symbol table, therefore no information". The marker
  string survives stripping, so a correct triage still recovers a lead — and a triage that
  conflates the export table with debug symbols reports this one as unstripped.
- **`triage_packed`** → catches "high entropy, therefore packed", *and* catches the weaker
  version of the same error: scoring the whole file. A correct triage localises the entropy
  to a read-only data section, observes that `.text` is normal, and keeps
  `NEXT decompile-bytecode`.

A single fixture could not separate these cases. `triage_packed` in particular only works as
a control because `.blob` is data rather than code — if it were an executable section at
7.995, the correct answer would flip to "packed".

## Reproducing the numbers

```bash
# whole-file entropy
node -e '
const fs=require("fs");
for(const f of process.argv.slice(1)){
  const d=fs.readFileSync(f), c=new Uint32Array(256);
  for(const b of d) c[b]++;
  let H=0; for(const n of c) if(n){const p=n/d.length; H-=p*Math.log2(p);}
  console.log(f.split("/").pop().padEnd(18), H.toFixed(3));
}' fixtures/build/triage_clean fixtures/build/triage_stripped fixtures/build/triage_packed
```

Per-section entropy for the packed fixture is in step 5 of `SKILL.md`; it is the same script.

## Provenance and legal

All three are compiled from C sources written for this repository. No third-party binary, no
malware sample, no commercial software, and no licence-check or activation target is used
anywhere in this repository. See `docs/legal.md`.

The packed fixture's blob is generated by `src/gen_packed.mjs` with a fixed xorshift32 seed,
so builds are byte-reproducible. The generator exits non-zero if the blob's measured entropy
falls below 7.99 — if a future edit stops the fixture exercising the signal, the build fails
rather than quietly testing nothing.

## Toolchain requirements

`gcc`, `strip`, `node`. All three ship with a stock developer machine.

If `strip` is missing, `triage_stripped` is still built but carries symbols, and its ground
truth no longer holds. The build script warns; `verify.sh` reports the reduced fixture count
rather than passing silently.

## Platform note

Sources are portable C; the artifacts are **PE32+ on Windows/MinGW and ELF on Linux/gcc**.
Ground truth relationships hold on both, absolute numbers do not:

| | PE (MinGW-w64) | ELF (gcc) |
|---|---|---|
| Section table reader | `objdump -h` | `readelf -SW` |
| Sections, `triage_clean` | 16 | ~30 |
| Bytes, `triage_clean` | ~83 KB | ~16 KB |
| Stripping reported as | "stripped to external PDB" | "stripped" |
| Custom section `.blob` | present | present |

`expected.md` lists the full comparison. This is the reason step 4 of `SKILL.md` counts
symbols with `nm` instead of testing for ELF's `.symtab`: a triage that hard-codes `readelf`
works on Linux CI and silently returns nothing on a Windows host.
